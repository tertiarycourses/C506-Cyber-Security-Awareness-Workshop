# Lab-05: Authorised Web-Risk Review in FauxBank

**Course:** Cyber Security Awareness Workshop  
**Course code:** C506  
**Time:** 40 minutes  
**Alignment:** LO1, LO3  
**Tool:** [FauxBank](https://pentest-fauxbank.vercel.app/)

## Scenario

A bank training application needs a safe, evidence-based review of authentication and input-handling risks.

## Safety and authorisation boundary

- Use only the named training tool and the mock files in this folder.
- Do not enter real passwords, personal data, payment details or confidential information.
- Do not test any other website, network, account or organisation.
- Stop immediately if the target, data or behaviour differs from the written scope.
- Prefer reversible actions and preserve synthetic evidence.

## Mock data

- `mock-fauxbank-test-plan.csv`
- `mock-test-accounts.csv`

## Detailed procedure

1. Confirm the scope is limited to the supplied FauxBank training site and mock accounts; do not test any other system.
2. Review the test plan and identify the expected safe outcome for authentication, authorisation and input validation.
3. Run only the non-destructive checks listed in the plan; never attempt data destruction, denial of service or persistence.
4. Record the request context, observed behaviour, risk, affected user and reproducibility without storing real credentials.
5. Map each observation to a vulnerability category and a defensive recommendation.
6. Create a one-page responsible report with evidence, impact, remediation and escalation priority.

## Completion standard

- Signed scope check
- Completed test plan
- Redacted screenshots
- Risk statements
- Responsible report

## Reflection

What evidence would make you reverse your decision, and who would need to know?
